# 업태/업종 코드·명 세트 동기화 — 설계

> 작성일: 2026-07-10
> 대상 화면: 회원 상세 모달(`MemberDetailModal.tsx`) 사업자 정보 카드
> 관련 필드: `serviceCode`/`serviceName`(업태), `itemCode`/`itemName`(업종)

## 배경

업태·업종은 백엔드에서 공통코드(`common_code`, 그룹코드 `SERVICE`/`ITEM`)로 관리되며, 코드와 명은 항상 한 세트로 움직여야 한다. 현재 회원 상세 화면(`BusinessCard` 컴포넌트, `CodePickerRow`)은 코드·명을 각각 독립적인 자유 입력 텍스트로 편집할 수 있어, 사용자가 코드만 바꾸거나 명만 바꿔서 세트가 깨진 상태로 저장될 수 있다. 저장 시점에 `serviceInvalid`/`itemInvalid`로 시각적 경고만 줄 뿐, 편집 중에는 세트 일치를 강제하지 않는다.

이 설계는 코드·명을 직접 수정하는 것을 "잘못된 편집"으로 간주하고, 편집 시 자동으로 공통코드 검색을 유도해 항상 유효한 세트로만 확정되도록 유도한다(단, 강제 차단은 하지 않음 — 아래 "저장 차단 여부" 참조).

## 핵심 동작

업태(SERVICE)·업종(ITEM) 모두 동일하게 적용한다.

1. **코드 필드 입력값 변경** → 즉시 명 필드를 로컬로 비운다 (저장 전, 화면 state만).
2. **명 필드 입력값 변경** → 즉시 코드 필드를 로컬로 비운다.
3. **Enter 또는 blur(포커스 이탈) 시**: 직전 확정 값(초기 로드 값 또는 마지막 검색 선택 값)과 실제로 값이 달라졌을 때만 아래를 수행한다.
   - 값이 그대로면(단순 클릭 이동 등) 아무 동작도 하지 않는다.
   - 입력값이 빈 문자열이면 검색을 열지 않는다.
   - `CommonCodeSearchModal`을 입력값을 검색어로 채워서 연다(`initialQuery`).
4. **검색 결과가 정확히 1건**이면 자동으로 그 항목을 선택 처리하고 모달을 닫은 뒤 코드+명을 함께 채운다. 이 자동 선택은 **모달이 열리는 최초 필터링 시점에만** 적용한다 — 모달이 열린 뒤 사용자가 검색어를 추가로 타이핑해 결과가 1건으로 좁혀지는 경우는 일반 수동 선택(클릭/Enter)으로 처리하며 자동으로 닫지 않는다.
5. **검색 결과가 0건 또는 2건 이상**이면 모달을 열어둔 채로 유지한다. 0건은 기존 "검색 결과가 없어요." 문구를 그대로 사용한다.

## 기존 요소와의 관계

- **수동 검색(돋보기) 버튼**: 그대로 유지한다. 빈 검색어로 전체 목록을 여는 기존 동작이며, 자동 선택 로직은 적용하지 않는다(사용자가 명시적으로 목록을 훑어보려는 의도이므로 자동으로 닫히면 안 됨).
- **저장 시 유효성 하이라이트(`serviceInvalid`/`itemInvalid`)**: 그대로 유지한다. 레거시 데이터 등으로 세트가 깨진 상태가 남아있을 수 있는 안전망 역할.
- **저장 버튼 차단 여부**: 자동 검색 모달이 열려 있는 동안에도 저장 버튼은 막지 않는다(기존과 동일하게 항상 클릭 가능). 세트가 깨진 상태로 저장을 시도하면 기존 유효성 하이라이트로만 안내한다.
- **모달을 선택 없이 닫은 경우(ESC/바깥 클릭)**: 입력했던 코드/명 값을 그대로 유지한다(직전 확정 값으로 되돌리지 않음). invalid 하이라이트가 표시된다.

## 구현 범위

### `CommonCodeSearchModal.tsx`

- `initialQuery?: string` prop 추가 — 전달되면 검색창 초기값으로 사용.
- `autoSelectSingleMatch?: boolean` prop 추가 — `true`이고, 모달이 열린 시점의 최초 필터링 결과가 정확히 1건이면 `onSelect`를 자동 호출한다. 이후 사용자가 검색어를 직접 타이핑해 결과가 바뀌는 경우에는 이 자동 선택을 재적용하지 않는다(1회성 체크).
- 데이터가 아직 로딩 중(`items == null`)이면 로딩 완료 후 1회만 이 체크를 수행한다.

### `MemberDetailModal.tsx` — `BusinessCard` / `CodePickerRow`

- 코드·명 각각에 "직전 확정 값" 추적 state 추가(초기 로드 값 또는 마지막 검색 선택 값으로 갱신).
- `onCodeChange`/`onNameChange` 시 상대 필드를 초기화하는 로직 추가.
- 코드·명 입력에 blur/Enter 커밋 핸들러 추가 — 확정 값과 다를 때만 검색 모달을 오픈(`initialQuery` + `autoSelectSingleMatch=true`)하고, 모달에서 선택 완료 시 "직전 확정 값"도 함께 갱신.
- 업태/업종 두 필드에 동일 로직을 공용 헬퍼(hook 또는 함수)로 추출해 중복을 피한다.

## 테스트 계획

- `CommonCodeSearchModal.test.tsx`(신규 또는 기존 확장): `initialQuery` prop이 검색창에 반영되는지, `autoSelectSingleMatch=true`이고 결과 1건일 때 `onSelect`가 자동 호출되는지, 결과 0건/2건 이상일 때는 자동 호출되지 않는지.
- `MemberDetailModal.test.tsx`(기존 확장): 코드 변경 시 명이 즉시 비워지는지, blur/Enter 시 값이 바뀐 경우에만 검색 모달이 열리는지(값이 안 바뀌면 안 열림, 빈 값이면 안 열림), 검색 결과 1건일 때 코드+명이 함께 채워지고 모달이 닫히는지, 모달을 선택 없이 닫으면 입력값이 그대로 남는지.

## 범위 밖

- 코드 필드의 숫자 전용 입력 제한 등 입력 형식 제약은 이번 설계에 포함하지 않는다(요청 범위 아님).
- 업태/업종 외 다른 공통코드 필드(파트너 코드 등)에는 이 패턴을 적용하지 않는다.
