### 확인 중 발견·수정한 이슈

1차 실행 시 프론트에 **"주문 동기화 실행에 실패했어요"**가 떴다. 그러나 DB의 `batch_execution_log`를 확인하니 서버에서는 실제로 34초 만에 `SUCCESS`로 정상 완료돼 있었다 — 즉 **실패가 아니라 클라이언트 타임아웃**이었다.

- 원인: `OrderSyncBatchJob.run()`이 동기(블로킹) 방식이라, HTTP 응답이 배치 완료까지(수십 초) 지연되는데 `client.ts`의 axios 인스턴스는 전역적으로 `timeout: 10_000`(10초)만 허용한다.
- 조치: 전역 `client.ts`의 타임아웃은 다른 API 호출에도 영향을 주므로 건드리지 않고, `runOrderSyncNow` 호출에만 `timeout: 120_000`(2분)을 개별 지정했다.
- 재검증: 수정 후 다시 클릭 → 정상적으로 "정상 완료"가 표시됨을 확인.

### 참고

- 이번 기능은 **백엔드 신규 개발이 전혀 없다** — 기존 `POST /api/admin/batch-schedules/order-sync/run?targetDate=`(이미 임의 날짜를 지원)를 화면에 노출한 것뿐이다.
- 사용자가 날짜를 21일 간격으로 바꿔가며 이 버튼을 반복 실행하면, 자동 청크 로직 없이도 임의 과거 기간을 수동으로 백필할 수 있다. 자동 반복(일괄 백필)은 이번 범위 밖으로 남겨뒀다.
