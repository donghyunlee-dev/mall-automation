# ATCS-216 Plan

## Requirement Summary

- 전체 상품 목록 카드 헤더에 엑셀 다운로드 버튼을 추가한다.
- 다운로드 파일은 현재 화면에 보이는 일부 행이 아니라 전체 상품 데이터를 모두 포함해야 한다.
- 다운로드 결과는 컬럼 헤더와 기본 서식이 정리된 `.xlsx` 파일이어야 한다.

## Business Context

- 운영자는 상품 목록 전체를 한 번에 내려받아 검토, 공유, 백업성 점검을 수행할 필요가 있다.
- 현재는 엑셀 업로드만 있고 전체 목록을 파일로 추출하는 기능이 없어 운영 효율이 떨어진다.
- 필터나 페이지네이션 결과만 내려받으면 전체 현황 확인 목적을 충족하지 못하므로 전체 데이터 기준 다운로드가 필요하다.

## Scope

- 전체 상품 목록 카드 헤더에 `엑셀 다운로드` 버튼 추가
- 전체 상품 데이터 기준 `.xlsx` 생성 로직 구현
- 엑셀 헤더, 컬럼 순서, 컬럼 폭, 파일명 등 기본 포맷 적용
- 빈 데이터 또는 로딩 상태에 대한 다운로드 가드 및 토스트 처리
- 관련 문서 및 테스트 추가

## Out Of Scope

- 서버 API 추가 또는 변경
- 업로드 기능 동작 변경
- 필터/정렬/페이지네이션 로직 변경
- 셀 배경색, 글꼴색 등 고급 엑셀 스타일링

## Impacted Modules

- `src/pages/DashboardPage.tsx`
- `src/pages/DashboardPage.module.scss`
- `src/utils/exportGoodsExcel.ts`
- `src/utils/exportGoodsExcel.test.ts`

## Architecture Considerations

- 엑셀 생성은 기존 의존성 `xlsx`를 그대로 활용해 프론트에서 처리한다.
- 버튼 클릭 핸들러는 페이지에 두고, 엑셀 데이터 변환과 파일 생성은 유틸로 분리해 UI와 비즈니스 로직을 분리한다.
- 다운로드 대상은 `pagedItems`나 `filteredItems`가 아니라 `allItems`를 사용해 전체 데이터를 보장한다.

## Risk Analysis

- 오픈소스 `xlsx`는 고급 셀 스타일 지원이 제한적이므로 이번 범위에서는 헤더/열 너비/시트명 수준의 포맷으로 맞춘다.
- 상품 상태와 코드검증 상태 문구를 파일용으로 다시 계산해야 하므로 화면 표현과 불일치가 생기지 않도록 기존 규칙을 그대로 복제해야 한다.
- 브라우저 환경의 파일 다운로드는 자동 테스트가 제한적이므로 데이터 변환 유틸 테스트와 수동 확인을 병행해야 한다.
