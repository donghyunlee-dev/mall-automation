# PAGES — 화면 설계 및 기능 명세

UI/UX 기준은 `docs/design/mockup.html`. 이 문서는 컴포넌트 구조와 기능 동작을 정의한다.

---

## 라우트 구조

```
/login           → LoginPage        (인증 불필요)
/goods           → GoodsPage        (상품 관리 — 세션 필요)
/members         → MembersPage      (회원 목록 — 세션 필요)
                   └ MemberDetailModal (회원 상세 모달 — 행 클릭 시 오버레이, 별도 라우트 없음)
/                → /goods 로 리다이렉트

* 보호 경로는 AuthedLayout(전역 Header + TabBar) 하위에 위치하며, 세션 없이 접근 시 /login으로 리다이렉트.
* 탭: 상품 관리(/goods) · 거래처 등록 관리(/members)
```

## 1. 로그인 페이지 (`/login`)

목업: `docs/design/mockup-login.html`

### 세션 확인 흐름 (페이지 마운트 시)

```
/login 진입
  │
  ▼
GET /api/auth/session  (credentials: 'include')
  │
  ├─ 200 유효 ──► / 로 리다이렉트 (이미 로그인됨)
  │
  └─ 401 무효 ──► 로그인 폼 표시
```

### 화면 구성

헤더(대시보드와 동일) + 중앙 정렬 카드. 카드 내부는 2단계 흐름.

**공통 요소**
- 자물쇠 아이콘 + 타이틀 "로그인" + 설명 문구
- 스텝 인디케이터: `① 이메일 입력 ──── ② 인증번호 확인`
  - 현재 스텝: 브랜드 레드 채움
  - 완료 스텝: 초록 채움 + ✓ 표시
  - 미완료 스텝: 회색 테두리

---

**Step 1 — 이메일 입력**

- 이메일 입력 필드 (placeholder: `name@s-food.com`)
- 힌트 문구: `@s-food.com 이메일 주소만 허용됩니다`
- `@` 포함 여부로 버튼 활성화 제어 (프론트 기본 검증)
- "인증 코드 발송" 버튼 → `POST /api/auth/email-verifications`
- 버튼 클릭 시 로딩 스피너 + "처리 중..." 표시
- 성공 시 Step 2로 전환 (이메일 입력 필드는 유지됨)

에러 박스 표시 조건:

| 상태코드 | 표시 메시지 |
|---|---|
| 400 | 이메일 형식이 올바르지 않거나 허용되지 않는 도메인이에요 |
| 429 | 잠시 후 다시 시도해주세요. (발송 횟수 초과) |
| 기타 | 오류가 발생했어요. 다시 시도해주세요 |

---

**Step 2 — 인증번호 입력**

- 초록 성공 박스: `{email} 으로 인증번호를 발송했어요`
- OTP 입력 필드: 숫자 6자리, 큰 글씨 중앙 정렬, `inputmode="numeric"`, `autocomplete="one-time-code"`
- 숫자 6자리 입력 완료 시 로그인 버튼 자동 활성화
- 타이머: `유효 시간 5:00` → 카운트다운, 1분 미만 시 빨간색 전환
- 재발송 버튼: 초기 60초 쿨다운 (`재발송 (N초)` → `재발송`)
- "로그인" 버튼 → `POST /api/auth/email-verifications/confirm`
- 성공 시 `window.location.href = '/'`
- "이메일 다시 입력" 링크 → Step 1로 복귀 (타이머 정지)

에러 박스 표시 조건:

| 상태코드 | 표시 메시지 |
|---|---|
| 401 | 인증번호가 일치하지 않아요. 다시 확인해주세요 |
| 409 | 이미 처리된 인증이에요. 재발송해주세요 |
| 410 | 인증번호가 만료됐어요. 재발송 버튼을 눌러주세요 |
| 429 | 시도 횟수를 초과했어요. 재발송해주세요 |
| 기타 | 인증에 실패했어요. 다시 시도해주세요 |

- 타이머 0 도달 시에도 동일한 만료 에러 표시 + 로그인 버튼 비활성화

---

### 세션 유지 흐름 (로그인 완료 후)

```
POST /api/auth/email-verifications/confirm 성공
  │
  └─ 백엔드가 Set-Cookie: SESSION=xxx; HttpOnly; Path=/; Max-Age=10800 응답
  │  (프론트는 credentials: 'include' 덕분에 브라우저가 자동 저장)
  │
  ▼
window.location.href = '/'
  │
  ▼
DashboardPage 마운트
  │
  ▼
GET /api/auth/session  (세션 재확인)
  │
  ├─ 200 ──► 정상 렌더링
  └─ 401 ──► /login 리다이렉트
```

모든 API 요청에 `withCredentials: true` (Axios) 또는 `credentials: 'include'` (fetch) 필수.

## 2. 상품 관리 페이지 (`/goods`)

전역 레이아웃(`AuthedLayout`: Header + TabBar) 하위 페이지. 본문은 상단 툴바(상태 동기화·자동 실행 설정) + 현황 요약 + 전체 상품 목록 + 오늘 변경 이력 순서로 구성.

> Iteration 08에서 단일 페이지(`/`)가 `/goods`로 이동하고, 헤더에 있던 동기화 컨트롤이 본문 툴바로 내려왔다.

---

### 2-1. 헤더 및 본문 툴바

**전역 헤더 (`Header.tsx`)** — 전역 요소만 포함
- 로고: `에쓰푸드몰 운영 관리` (에쓰푸드몰 부분 브랜드 레드)
- TabBar: `상품 관리` / `거래처 등록 관리` (활성 탭 하단 보더 강조)
- 아바타 드롭다운 버튼 (이메일 + 이니셜 아이콘)

**아바타 드롭다운 (`AvatarDropdown.tsx`)**
- 상단: 사용자 이름, 이메일
- 로그아웃: 버튼 클릭 → 확인 모달 → 세션 삭제 → `/login` 리다이렉트

**상품 관리 본문 툴바** — 동기화 컨트롤(헤더에서 이동)
- 마지막 갱신 시각 (`갱신 HH:MM:SS`)
- "지금 바로 상태 동기화" 버튼 → `POST /api/admin/batch-schedules/product-sync/run`
  - 실행 중: 스피너 + "동기화 중..." 텍스트, 버튼 비활성화
  - 완료: 원래 상태 복원, 상품 목록 및 변경 이력 갱신
- 자동 실행 시간 설정: 숫자 입력(분) + 적용 버튼 → 확인 모달 → `PUT /api/admin/batch-schedules/product-sync`

---

### 2-2. 현황 요약 카드 (`SummaryCards.tsx`)

**데이터 가공**: API 응답 데이터를 프론트에서 직접 가공해 집계한다. 별도 API 없음.

| 카드 | 데이터 출처 | 클릭 동작 |
|---|---|---|
| 마지막 실행 | 배치 상태 API 응답 (`lastStartedAt`, `lastStatus`) | 없음 |
| 현재 품절 | 상품 목록에서 `soldOutYn === 'Y'` 카운트 | 품절 필터 자동 적용 + 상품 목록 스크롤 |
| 오늘 상태 변경 | 배치 실행 응답의 변경 이력 건수 | 변경 이력 섹션으로 스크롤 |

현재 품절 카드 표시 형식: `8개 / 20개` (품절 수는 크고 빨간색, 전체는 작고 연한색)

### 2-3. 전체 상품 목록 (`ProductTable.tsx`)

**카드 헤더**
- 타이틀: `전체 상품 목록`
- 타이틀 옆 카운트 pill: `현재노출수/전체수개` (필터/검색 변경마다 실시간 갱신)
- 우측: 엑셀 일괄 업로드 버튼, 상품 추가 버튼

**검색/필터 바 (`ProductSearchBar.tsx`)**
- 검색 입력: placeholder `고도몰 상품코드, ERP 품목코드, 상품명...`
  - 프론트 필터링 (입력 즉시 반응)
- 필터 버튼: `전체` / `품절` / `판매중` / `범용` / `전용`
  - 한 번에 하나만 활성화
  - 활성 버튼에 색상 표시 (`style-guide.md` 참고)

**테이블 컬럼**

| 컬럼명 | 정렬 가능 | 비고 |
|---|---|---|
| 고도몰 상품코드 | ✅ | |
| ERP 품목코드 | ✅ | |
| 상품명 | ✅ | 오늘 등록/수정 시 `NEW` 뱃지 표시 |
| 구분 | ✅ | 범용(회색) / 전용(보라) 뱃지 |
| 판매 상태 | ✅ | 판매중(초록 채움) / 품절(주황 채움) 뱃지 |
| 동기화 일자 | ✅ | |
| 등록·수정일 | ✅ | `수정 YYYY.MM.DD` 또는 `등록 YYYY.MM.DD` |
| 등록/수정자 | ✅ | 사용자 이름 |
| 액션 | ❌ | 행 호버 시 수정/삭제 버튼 표시 |

- 10개씩 페이지네이션 (`Pagination.tsx`)
- 기본 정렬: 등록·수정일 최신순
- 컬럼 헤더 클릭 시 오름차순/내림차순 토글
- 정렬 아이콘: 비활성 `↕`, 오름차순 `↑`, 내림차순 `↓`

**행 액션**
- 수정 버튼 → `ProductEditModal` 열기

## 3. 모달

### ProductAddModal — 상품 추가

**입력 필드**
- 고도몰 상품코드 (필수)
- ERP 품목코드 (필수)
- 상품명 (필수)

**저장 동작**
- `POST /api/goods` 호출
- 성공 시 모달 닫기 + 목록 새로고침 + 토스트

---

### ProductEditModal — 상품 수정

**수정 가능 필드**: 상품명, ERP 품목코드, 구분
**수정 불가 필드**: 고도몰 상품코드 (disabled 처리)

**저장 동작**
- `PUT /api/goods/{id}` 호출
- 성공 시 모달 닫기 + 목록 새로고침 + 토스트

---

### ProductDeleteModal — 상품 삭제 확인

- 삭제 대상 상품명, 고도몰 코드, ERP 코드, 구분 표시
- 경고 문구: "삭제하면 자동화 대상에서 제외되며 복구할 수 없어요."
- `DELETE /api/goods/{id}` 호출
- 성공 시 모달 닫기 + 목록 새로고침 + 토스트

---

### ExcelUploadModal — 엑셀 일괄 업로드

**탭 구조**: 파일 업로드 탭

**파일 업로드**
- 드래그 & 드롭 + 클릭 선택 (`xlsx`, `xls`)
- 파일 선택 완료 시 파일명 표시 + 삭제 버튼
- "업로드 적용" 버튼 → `POST /api/goods` (품목 추가와 동일 API, 배열 형태로 전송)
- 요청: 품목 객체 배열, 응답: `{ items: [...] }` 형태로 건별 결과 반환
- 업로드 결과 토스트 표시

**엑셀 양식 안내**

| 열 | 컬럼명 | 예시 |
|---|---|---|
| A | 고도몰 상품코드 | G001001 |
| B | ERP 품목코드 | N14670100 |
| C | 상품명 | 에쓰푸드 모둠전 500g |
| D | 구분 | 범용 또는 전용 |

---

## 4. Teams 웹훅 알림

프론트엔드에서 Power Automate HTTP 트리거 URL로 POST 요청을 전송하며, Power Automate가 Teams 채팅에 메시지를 게시한다. 웹훅 URL과 대시보드 URL은 환경변수(`VITE_TEAMS_WEBHOOK_URL`)로 관리한다 (코드 하드코딩 금지).

### 발송 조건

| 조건 | 대시보드 링크 |
|---|---|
| 폴링으로 자동 배치 완료 감지 + 변경 이력 있음 | O |
| 오류 발생 (배치 실패 등) | X |

- 변경 이력이 없는 경우 알림 미발송

### 상태 변경 알림 메시지 포맷

```
📦 에쓰푸드몰 판매 상태 변경 알림
실행 시각: {실행시각}
변경 건수: {N}건

| 상품명 | 고도몰 코드 | 변경 내용 |
(변경 품목 rows 동적 생성)

[대시보드 바로가기] → {DASHBOARD_URL}
```

- 변경 품목 rows는 폴링 응답 데이터 기반으로 동적 생성
- 변경 내용: `판매중 → 품절` 또는 `품절 → 판매중`

### 오류 알림 메시지 포맷

```
⚠️ 에쓰푸드몰 자동화 오류 발생
발생 시각: {발생시각}
오류 내용: {오류메시지}

자동화 서비스가 정상적으로 동작하지 않을 수 있습니다.
담당 개발자에게 문의해주세요.
```

**검색/필터 (`MemberSearchBar.tsx`)**
- 등급 드롭다운: 전체(ALL) | 사업자(BUSINESS) | B2B — 일반(GENERAL) 제외
- 검색 타입 드롭다운: 아이디(MEM_ID) | 이름(NAME) | 거래처코드(PARTNER_CODE) | 거래처명(PARTNER_NAME) | 이메일(EMAIL) | 휴대폰(CELL_PHONE)
  - PARTNER_CODE·PARTNER_NAME은 백엔드 추가 예정 (착수 전 `api-spec-member.md` 확인)
  - MEM_ID 외 선택 시 placeholder: "정확히 일치하는 값 입력"
- 키워드 입력 + 지우기(X) 버튼 + 조회 버튼 (Enter 키 제출)
- 우측 끝: 페이지 크기 드롭다운 (기본 10개씩 보기, 10 | 20 | 30 | 50)

**테이블 (`MemberTable.tsx`)** — `GET /api/members` (마스킹 응답)
- 컬럼: 회원번호·아이디·등급(배지)·거래처코드·거래처명·승인·가입일
- 정렬 가능: `mem_no, mem_id, group_sno, app_fl, entry_dt, last_login_dt, sale_amount`
- 행 클릭 → 상세 모달 오픈 (고도몰 링크는 stopPropagation)
- 정렬 불가 컬럼: 암호화·마스킹 필드(이름·이메일·휴대폰) 및 파트너 필드(거래처코드·거래처명)
- 빈 상태: "아직 동기화된 회원이 없습니다" + 엑셀 업로드 버튼 / "검색 결과가 없습니다" + 초기화 버튼
- 하단: `Pagination.tsx`

**엑셀 업로드 (`MemberUploadModal.tsx`)** — `POST /api/members/uploads` (단일 호출)
- 파일 드롭 → 종류 자동판별(LIST/TEMPLATE) → 손상파일 안내 → `applyDeletion` 체크(기본 해제) → 업로드 → 결과 요약(신규/갱신/탈퇴/실패)
- `deletionSkipped`(삭제 대상 10% 초과 보류) 시 경고 표시

### 6-2. 회원 상세 (모달 오버레이 — `MemberDetailModal`)

목록 행 클릭 시 모달 오버레이로 표시. 복호화 평문 표시(마스킹 없음). 조건부 섹션 구성.

- 헤더: 아이디 / 등급 배지 / `고도몰 어드민 열기` / `×` 닫기
- 기본 정보 섹션 (항상) — 읽기 전용, 엑셀 재업로드로만 갱신

- 에쓰푸드 거래처 정보 섹션 (`group_sno === 9`) — 항상 편집 가능 상태
- 추가 정보 섹션 (ex1~ex6 중 값 존재 시)
