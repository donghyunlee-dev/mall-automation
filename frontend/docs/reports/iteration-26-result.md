## 완료 범위

운영에서 "주문 동기화 실행에 실패했어요"가 표시되지만 실제로는 데이터가 정상 저장되는 문제를 수정했다. 원인은 동기 방식 `/run` 엔드포인트가 실제 운영 주문량에서 프론트 타임아웃(120초)보다 오래 걸릴 수 있고, 클라이언트가 타임아웃으로 포기해도 백엔드는 계속 실행되어 결국 정상 저장하기 때문이다.

## 수정 파일

| 파일 | 변경 내용 |
|------|----------|
| `frontend/src/api/orderSync.ts` | `RUN_TIMEOUT_MS` 120초 → 300초 |
| `frontend/src/hooks/useOrderSync.ts`(+test, TDD) | `runNow` catch에서 axios 타임아웃(`ECONNABORTED`)과 실제 실패를 구분해 다른 메시지 표시 |

## 임시방편임을 명확히

이번 수정은 타임아웃 값을 늘리고 메시지를 구분한 것으로, 근본적으로 `/run`이 동기·블로킹 방식이라는 구조는 그대로다. 운영 주문량이 더 늘면 300초도 초과할 수 있다. 사용자가 "임시방편(빠름)"으로 명시적으로 선택했으며, 근본 해결(비동기 실행 + 폴링, upsert N+1 개선)은 별도 작업으로 남겨둔다.
