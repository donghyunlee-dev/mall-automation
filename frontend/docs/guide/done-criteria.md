# ✅ Done Criteria

## 🎯 목적

이 문서는 React Frontend 개발 작업이 완료되었는지 판단하기 위한 기준을 정의한다.

목표는 다음과 같다.

- 구현 완료 여부를 명확하게 판단한다.
- Claude가 작업 종료 시점에 일관된 기준을 적용하도록 한다.
- 품질 기준을 코드 수준이 아니라 결과 기준으로 검증한다.

---

## 📌 기본 원칙

- 기능 구현만으로 완료로 판단하지 않는다.
- 빌드 유효성, 구조, 오류 처리까지 포함해야 완료로 본다.
- 요구사항 범위를 초과한 작업은 완료 조건에 포함되지 않는다.
- 완료 기준을 만족하면 추가 개선 없이 작업을 종료한다.

---

## 🧱 기능 요구사항 기준

다음 항목을 모두 만족해야 한다.

- 요구사항에 정의된 기능이 정상 동작한다.
- 모든 사용자 인터랙션이 의도한 UI 동작을 수행한다.
- 정상 케이스와 실패 케이스가 모두 UI에 반영된다.
- API 응답이 `docs/product/api-spec.md` 명세와 일치하게 처리된다.
- 상태 변화가 의도대로 수행되며 부작용이 없다.

---

## 🏗️ 컴포넌트 구조 기준

- Page, Component, Hook, API 역할이 분리되어 있다.
- 컴포넌트에 비즈니스 로직이 존재하지 않는다 — 커스텀 훅으로 분리한다.
- 컴포넌트에서 `axios`를 직접 호출하지 않는다.
- Props 타입이 각 파일 상단에 `interface`로 정의되어 있다.

---

## 🔌 API 분리 기준

- 모든 API 호출은 `src/api/` 함수를 통해서만 처리된다.
- 컴포넌트 또는 훅에서 `axios`를 직접 호출하지 않는다.
- `client.ts` 인터셉터가 401 오류를 `/login`으로 리다이렉트한다 (단, `/api/auth/` 경로 제외).
- API 응답 타입이 완전히 정의되어 있으며 `any`를 사용하지 않는다.

---

## 🗃️ 타입 및 데이터 기준

- 모든 Props, API 요청, API 응답 타입이 명시적으로 정의되어 있다.
- `any` 타입이 사용되지 않는다.
- 타입은 `src/types/`에 정의되고 컴포넌트와 훅에서 재사용된다.

---

## 🎨 스타일 기준

- 모든 스타일은 CSS Modules (`.module.scss`)를 사용하며 인라인 스타일이 없다.
- 모든 디자인 토큰은 `_variables.scss`에서 가져온다.
- 구현된 UI가 목업(`docs/design/mockup.html` 또는 `docs/design/mockup-login.html`)과 일치한다.
- CSS 변수명과 클래스명이 목업 기준을 따른다.

---

## 🧪 빌드 및 린트 검증 기준

- `npm run build`가 오류 없이 완료된다.
- `npm run lint`가 오류 없이 통과한다.
- TypeScript 오류가 존재하지 않는다.
- 사용하지 않는 import 또는 변수가 없다.

---

## 🧾 오류 처리 기준

- 오류가 숨겨지지 않는다.
- API 오류가 사용자에게 명확히 반영되거나 명시적으로 처리된다.
- 발생할 수 없는 케이스에 대한 오류 처리를 추가하지 않는다.
- 유효성 검사는 시스템 경계(사용자 입력, API 응답)에서만 수행한다.

---

## 🧹 코드 품질 기준

- 중복 코드가 존재하지 않는다.
- 함수 또는 훅은 하나의 책임만 가진다.
- 의미 있는 이름이 사용되었다.
- 불필요한 주석이 없다.
- 사용하지 않는 코드나 파일이 도입되지 않는다.

---

## 🔐 보안 기준

- 토큰, 인증 정보 등 민감한 값이 소스 코드에 하드코딩되지 않는다.
- 사용자 입력이 시스템 경계에서 검증된다.
- 인증 흐름(`withCredentials: true`, 세션 쿠키)이 정상 동작한다.

---

## ⚙️ 실행 및 검증 기준

다음 명령이 정상 수행되어야 한다.

```bash
npm run build
npm run lint
```

- `docs/plan/iteration/iteration-XX-plan.md`
- `docs/test/results/iteration-XX-test-result.md`
- `docs/reports/iteration-XX-result.md`

## 🧭 Claude 종료 조건

Claude는 다음 조건을 모두 만족하면 작업을 종료해야 한다.

- Done Criteria 모든 항목을 만족한다.
- 추가 개선 없이 현재 요구사항 범위를 충족한다.
- 빌드와 린트가 오류 없이 통과한다.
- 변경 범위가 최소화되어 있다.

---

## 🚫 완료로 인정되지 않는 경우

다음 경우 작업은 완료로 간주되지 않는다.

- UI가 목업과 일치하지 않는 경우
- Props 또는 API 응답 타입에 `any`가 사용된 경우
- 컴포넌트에 인라인 스타일이 존재하는 경우
- 비즈니스 로직이 컴포넌트 내부에 직접 존재하는 경우 (훅으로 분리되지 않은 경우)
- 컴포넌트 또는 훅에서 `axios`를 직접 호출하는 경우
- API 오류 상태가 처리되지 않은 경우
- 빌드 또는 린트가 실패하는 경우
- 이터레이션 문서가 작성되지 않은 경우

---

## ✍️ 최종 체크리스트

- 요구사항을 정확히 구현했는가
- UI가 목업과 일치하는가
- 빌드가 오류 없이 통과하는가
- 린트가 오류 없이 통과하는가
- 모든 타입이 명시적으로 정의되고 `any`가 없는가
- 비즈니스 로직이 커스텀 훅으로 분리되었는가
- 모든 API 호출이 `src/api/`를 통하는가
- 스타일이 CSS Modules와 `_variables.scss`만 사용하는가
- 변경 범위가 최소인가
- 이터레이션 문서가 작성되었는가

위 항목을 모두 만족해야 작업을 완료로 판단한다.
