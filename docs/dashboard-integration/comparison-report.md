## 1. 데이터 정합성 — 상세

### 1.1 비회원(게스트) 주문 누락 (🔴 가장 심각)

**원인 추정**: `GodoOrderResponseParser`가 `memberId.isBlank()`인 주문을 전부 건너뛴다(`backend/.../GodoOrderResponseParser.java`). 원본 파이프라인은 비회원 주문도 `구분자_비회원포함`이라는 별도 식별자로 포함시켜 "비회원" 등급으로 집계한다.

**증거 (2026-09-03 일간)**:

| 항목 | 원본 | 우리 | 차이 |
|---|---|---|---|
| 총 매출 | 9,180,395원 | 8,747,668원 | -432,727원 |
| 총 주문 건수 | 102건 | 95건 | -7건 |
| 총 주문자 수 | 95명 | 88명 | -7명 |
| 객단가(AOV) | 90,004원 | 92,081원 | +2,077원 |

원본 일간 등급별 상세 지표(우리는 이 행 자체가 없음):

| 회원등급 | 매출액 | 주문건수 | 주문자수 |
|---|---|---|---|
| 비회원 | 583,409원 | 8건 | 8명 |

**주간(2026-08-31~09-03) 기준도 동일 패턴**: 원본 "비회원" 34건/34명/3,097,027원이 우리 시스템에는 존재하지 않음.

### 1.2 회원등급 롤업(요약) 로직 미적용 (🔴 심각)

원본은 `회원등급명_요약`이라는 파생 컬럼으로 세부 등급을 요약해서 보여준다. 실제 확인된 원본 등급 체계(탭에 따라 3~5개만 노출):

- **사업자회원** (화이트/로제/VIP/레드 등 세부 등급을 전부 하나로 합산)
- **비회원**
- **일반회원**
- **기능장회원**
- **B2B 거래처**

반면 우리 등급별 상세 테이블은 세부 등급을 그대로 노출한다:

- 사업자회원_화이트, 사업자회원_로제, 사업자회원_VIP, 사업자회원_레드 (4개 행으로 분리)
- 일반회원, 기능장회원, B2B 거래처는 원본과 동일하게 별도 행으로 존재
- 비회원 행 자체가 없음(1.1과 동일 원인)

**영향 범위**: 등급별 매출 비중(도넛), 등급별 상세 지표 테이블, 인기 품목과 무관하지만 **일별/월별/분기별 실적 상세 피벗 테이블과 그 하단 등급별 라인 차트**까지 전부 영향 — 원본은 5개 라인(사업자회원/비회원/일반회원/기능장회원/B2B거래처)인데 우리는 세분화된 6~7개 라인이 표시된다.

**참고**: `docs/dashboard-integration/sfood-mall-dashboard-current-state.md`의 6장/9장에는 이 "회원등급명_요약" 매핑 로직이 별도로 문서화되어 있지 않다 — 통합 설계 당시 이 부분이 누락된 것으로 보인다.

### 1.3 등급별 매출액 소폭·중폭 불일치 (🟡 확인 필요)

비회원 누락을 감안하고 "사업자회원" 계열만 그룹 합산해서 비교해도 완전히 일치하지 않는다.

**2026-09-03 일간**:
- 원본 "사업자회원" 그룹 합계: 8,353,209원 / 89건 / 82명
- 우리 4개 세부 등급 합계: 8,503,891원 / 90건 / 83명 (화이트 4,465,952 + 로제 2,093,685 + VIP 620,898 + 레드 1,323,356)
- 차이: +150,682원 / +1건 / +1명 (약 1.8% 과다 집계)

**2026-08-31~09-03 주간**은 이 격차가 상대적으로 작다(사업자회원 그룹: 원본 38,888,745원/355건/311명 vs 우리 합계 39,039,428원/356건/312명, 약 0.4% 차이) — 근소한 타이밍/반올림 차이로 보인다.

**그러나 "일반회원" 등급은 격차가 훨씬 크다**:
- 주간 기준 — 원본: 1,801,660원 / 23건 / 23명, 우리: 5,276,206원 / 24건 / 24명 (거의 3배 차이, 주문 1건 차이인데 매출은 3,474,546원이나 차이남)

**가설**: 게스트(비회원) 주문 중 일부가 고도몰 API 응답에서 `memId`가 완전히 빈 문자열이 아니라 특정 placeholder 값으로 내려오는 경우가 있고, 이 경우 우리 파서가 걸러내지 못해 "일반회원"으로 잘못 분류되고 있을 가능성이 있다. 원본의 "회원등급명_요약" 로직은 이런 케이스를 정확히 "비회원"으로 식별하는 것으로 추정된다. **백엔드 로그/원본 데이터 파이프라인 로직 확인이 필요한 항목.**

### 1.4 2년 백필 미구현으로 인한 과거 데이터 공백 (🟡 기존에 알려진 Open Gap, 화면 영향 큼)

`OrderSyncBatchJob`은 21일 롤링 윈도우만 수집하므로(`backend/docs/tasks/dashboard-order-sync/result.md`에 이미 Open Gap으로 기록됨), 아래 화면이 사실상 텅 빈 것처럼 보인다:

- 월간 탭 "최근 2개년 추이": 21개월 중 마지막 2개월(2026-08, 2026-09)만 값이 있고 나머지 19개월은 0
- 월간 탭 "월별 실적 상세" 피벗: 동일하게 대부분 0
- 분기 탭 "최근 8분기 추이"/"분기별 실적 상세": 8분기 중 마지막 1분기(2026-3Q)만 값 존재
- "전년 동월/동분기 비교"의 "전년" 쪽 데이터가 0으로 나옴(원본은 예: 2025-09 매출 417,473,125원인데 우리는 이 값 자체를 조회할 수 없음)

원본은 2년 이상 누적된 실데이터(Parquet 스냅샷)를 갖고 있어 이 문제가 없다. **2년 백필 기능(Open Gap으로 이미 등록됨)을 구현하지 않으면 월간/분기 탭의 "추이"·"실적 상세"·"전년 비교" 섹션은 실사용 시 대부분 의미 없는 값(0)을 보여주게 된다.**

## 2. 차트/컴포넌트 구성 비교

### 2.1 일치하는 부분 (확인됨)

| 항목 | 확인 내용 |
|---|---|
| 탭 구성 | 일간(⚡)/주간(📈)/월간(🏆)/분기(📊) 4개, 아이콘·라벨 문구까지 동일 |
| 레이아웃 비율 | 추이차트+파이 행 = 2:1 비율(원본 `st.columns([2,1])` ↔ 우리 `.grid2` 2fr/1fr), 상세테이블+인기품목 행 = 1:1(원본 `st.columns(2)` ↔ 우리 `.grid2Even`) |
| 콤보 차트 색상 | 매출액 막대 `#636EFA`(파랑), 주문건수 라인 `#EF553B`(빨강) — 원본 `plot_combo_chart` 함수와 정확히 일치 |
| 핵심 지표 카드 개수 | 일간/주간 7개, 월간/분기 8개(ARPPU 추가) — 동일 |
| 등급별 상세 테이블 컬럼 | 매출액/주문건수/주문자 수/건당 SKU/건당 수량/AOV(객단가)/[ARPPU] 순서 동일 |
| 피벗 테이블 조회 항목 순서 | 일별/월별 실적 상세 모두 매출액→주문건수→주문자수→(건당수량→건당SKU→AOV→ARPPU) 순서 동일 |
| "매출액 단위: 천 원" 표기 및 스케일링 | 피벗 테이블에서 매출액을 1000으로 나눠 표시하는 것까지 동일 |
| 등급별 라인 차트 존재 | 월별/분기별 실적 상세 하단에 "등급별 {선택항목} 추이" 라인 차트 — 존재 여부 자체는 동일(값 구성은 1.2/1.4 이슈로 다름) |

### 2.2 차이나는 부분

#### (a) 인기 품목 차트 스타일
- **원본**: 막대 색상이 매출액 크기에 따라 그라데이션(연한색→진한색), 막대 끝에 주문수량 텍스트 라벨이 항상 표시됨(`texttemplate='%{text:,}개'`)
- **우리**: 단색(`#636efa`) 막대, 수량은 툴팁에서만 확인 가능 — 라벨 상시 노출 없음

#### (b) 날짜/기간 라벨 포맷
| 위치 | 원본 포맷 | 우리 포맷 |
|---|---|---|
| 일간 "최근 20일" x축 | `26-08-15(토)` (요일 포함) | `2026-08-15` |
| 주간 "최근 5주" x축 | `26/08/03` (주 시작 월요일) | ISO 날짜(주 마지막 일요일 기준) — **요일 기준점 자체도 다름**(원본=주 시작 월요일, 우리=주 종료 일요일) |
| 월간 "일별 실적 상세" 컬럼 | 확인 안 됨(캔버스 렌더링) | `2026-09-01` 등 전체 날짜 |
| 월간 "최근 2개년 추이"/"월별 실적 상세" | `25-01` (2자리 연도-월) | `2025-01` (월별 피벗은 슬라이스 처리로 `YYYY-MM`), 트렌드 차트는 `2025-01-31`(전체 날짜) |
| 분기 "최근 8분기"/"분기별 실적 상세" | `25-1Q` | `2025-03-31`(분기 말일 전체 날짜) |

원본은 사람이 읽기 쉬운 축약 라벨을 일관되게 쓰는 반면, 우리는 대부분 API가 내려주는 원본 날짜 문자열을 그대로 표시하고 있어 **특히 월별/분기별 실적 상세 표의 헤더가 원본보다 훨씬 길고 읽기 불편함**.

#### (c) 월간 "일별 출고 추이"/"등급별 매출 비중" 라벨의 기준일 (원본 특이 동작)
원본 코드(`app.py`)를 보면 필터링은 `OMS출고일`(=배송일자+1) 기준으로 하면서, x축 라벨은 `배송일자`(원본 필드, OMS출고일보다 하루 이전)를 그대로 사용한다. 즉 원본 화면에 "26-08-31"로 표시된 막대가 실제로는 OMS출고일 "2026-09-01" 데이터다. 이는 원본 자체의 표시상 특이점(일종의 오프바이원)으로, 우리 구현은 이 특이점 없이 실제 필터 기준(SHIPPED/OMS출고일)을 그대로 라벨로 쓴다 — **원본을 "충실히" 재현하려면 이 오프바이원까지 맞출지, 아니면 우리처럼 정확한 라벨을 유지할지 결정이 필요**.

#### (d) 축 제목
원본 차트에는 X축("주문시간", "주차 (Week)" 등)·Y축("금액", "매출액", "주문건수") 제목이 붙어 있다. 우리 Chart.js 설정에는 축 제목이 없다(`scales: { y: { beginAtZero: true } }` 등 최소 설정).

#### (e) 도넛 차트 hole 비율
원본 `px.pie(..., hole=0.4)` — 40% 홀. 우리 Chart.js Doughnut은 기본 cutout(약 50%)을 그대로 사용 — 시각적으로 원본보다 구멍이 살짝 더 크다. 결정적인 차이는 아니나 픽셀 단위로 다름.

#### (f) 인기 품목/잠봉 슬라이스 분리 차트
원본은 "일간 인기 품목 Top 6" 아래에 "🥩 잠봉 슬라이스 판매 비중" 전용 차트(400g/500g냉동/500g냉장 세 품목 판매 비중)가 4개 탭 전부에 별도로 존재한다. 우리는 Iteration 11 계획 단계에서 "top-items API가 이미 잠봉을 롤업해서 반환하므로 별도 차트 생략"으로 의도적으로 결정했다(문서화됨). **기능 자체가 없는 것은 의도된 단순화이지만, 잠봉 슬라이스 냉장/냉동 각 품목의 개별 판매 비중을 보고 싶다는 요구가 있다면 재검토 필요.**

## 7. 비교 방법 및 한계

- 두 시스템 모두 **실데이터**로 비교했으나 완전히 같은 순간의 스냅샷은 아니다(원본은 Supabase 캐시 데이터, 1시간 TTL; 우리는 검증 세션 중 라이브로 동기화한 데이터). 다만 두 시스템의 조회 시점 차이는 수 분~수십 분 이내였고, 위에서 확인된 격차(특히 비회원 누락, 등급 롤업 차이)는 시점 차이로 설명되지 않는 구조적 차이다.
- 원본의 일부 표(피벗 테이블 셀 값)는 Streamlit이 캔버스/이미지로 렌더링해 접근성 트리에서 텍스트를 추출할 수 없어, 스크린샷으로 시각 구조만 확인하고 정확한 숫자는 비교하지 못한 셀이 있다(주로 월별/분기별 실적 상세의 과거 구간).
- 잠봉 슬라이스 세부 차트, 인기 품목 차트의 그라데이션 색상 등은 시각적 확인에 기반한 것으로, 정확한 색상 코드까지는 추출하지 않았다.
