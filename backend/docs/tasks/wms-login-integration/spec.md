# WMS 로그인 연동 스펙

## 문제 정의

로그인 화면에서 시작해 WMS 로그인 API를 호출하고, 로그인 결과로 받은 세션 쿠키를 이후 요청에 사용하는 규칙이 필요하다.

## 배경

소비 서비스는 로그인 화면과 로그인 API를 연결해야 한다. 이후 WMS의 다른 기능은 별도 문서로 다룬다.

## 범위

- 로그인 화면에서 필요한 입력값 정의
- WMS 로그인 요청 정의
- 로그인 결과와 세션 쿠키 사용 순서 정의
- 비밀번호 SHA-256 해시 처리 규칙 정의

## 범위 제외

- 새로운 로그인 엔드포인트 추가
- 프로젝트 내부 경로나 파일명 설명

## 수용 기준

- 로그인 화면에서 받아야 하는 값이 설명되어야 한다
- 로그인 API 요청 형식이 설명되어야 한다
- 로그인 결과값이 설명되어야 한다
- 세션 쿠키 사용 순서가 설명되어야 한다
- 원문 비밀번호를 어떻게 SHA-256 해시해야 하는지 설명되어야 한다
- 로그인 이외의 WMS 기능 설명은 없어야 한다

## 엣지 케이스

- 비밀번호가 원문으로 들어오는 경우
- 비밀번호가 이미 SHA-256 해시된 경우
- 로그인 응답에 `Set-Cookie`가 없는 경우
- 로그인 후 세션이 만료되는 경우

## 가정

- 로그인은 쿼리 문자열을 사용하는 `GET` 요청이다
- 세션 쿠키는 메모리에서만 보관한다
- 소비 서비스는 로그인과 이후 API 요청에 같은 세션을 사용한다
